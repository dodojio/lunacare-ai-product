1. 背景与目标

1.1 背景

在 Case 01 对 Flo Health 的竞品分析中，我们发现：34%的App Store差评提及"预测不准"，但更深层的问题是——用户不知道预测有多准。现有产品给出一个确定的日期，但不提供置信度、误差范围或预测依据。当预测出错时，用户感受到的不是"AI在学习"，而是"AI在骗我"。

学术研究也证实：用户对"透明的AI"信任度比"准确的AI"高23%（CHI 2024）。置信度透明不是锦上添花，而是建立AI信任的核心机制。

1.2 产品目标

Goal
让用户在查看预测时，能够理解"这次预测有多可信"、"为什么这么预测"，并在数据不足时获得诚实的反馈而非虚假的确定性。

1.3 成功指标

指标定义目标
Confidence查看率首页预测卡片曝光后，点击查看置信度详情的比例≥40%
预测解释阅读完成率进入预测解释页后，滚动到底部的比例≥60%
低置信度用户记录提升率看到低置信度提示后，7天内新增记录的比例≥25%
预测相关差评率差评中提及"预测不准""骗人"的比例≤15%

2. 用户故事

US-01
作为周期不规律的用户，我想知道这次预测有多准，这样我可以决定是否需要做准备。
AC: 首页预测卡片显示置信度等级（高/中/低）+ 置信区间（±N天）
US-02
作为好奇的用户，我想知道AI为什么这么预测，这样我可以判断是否可信。
AC: 点击"为什么这么预测"可查看预测依据（使用了哪些数据、各因素权重）
US-03
作为新用户，我只有很少的记录数据，我希望App诚实告诉我预测不准，而不是给我一个假的确定日期。
AC: 数据不足3个周期时，显示低置信度状态，并提示"多记录可以提高准确度"
US-04
作为经期推迟的用户，我想知道推迟是否正常、可能原因是什么，而不是被一个"延迟警告"吓到。
AC: 推迟场景下，置信度重新计算，显示分级说明（正常波动/需关注/建议就医）+ 可能原因
US-05
作为注重隐私的用户，我想知道哪些数据被用于预测，这样我可以决定是否授权。
AC: 预测依据页显示当前使用的数据类型，未授权的数据标注"未启用"

3. 功能逻辑与规则

3.1 置信度计算规则

置信度不是AI模型的原始概率输出，而是经过产品层处理的用户可理解指标。综合以下因素计算：

因素权重说明
数据量35%已记录周期数（<3个周期大幅降权）
数据质量20%记录完整性、是否有缺失月份
周期规律性25%历史周期标准差（标准差越大置信度越低）
多协变量覆盖20%是否接入睡眠/运动/症状等额外数据

3.2 置信度分级与产品层处理

这是本功能最核心的设计：不同置信度对应完全不同的产品展示策略，而不是简单显示一个百分比。

🟢 High Confidence（≥80%）
  • 展示：正常预测卡片，显示预测日期 + "预测较准"标签
  • 文案："预计X月X日来，基于你N个周期的数据，预测较准确"
  • 置信区间：±2天，小字显示
  • 交互：可点击查看预测依据
  • 推送：经期前2天正常提醒
🟡 Medium Confidence（50-80%）
  • 展示：预测卡片明确标注"预测有一定不确定性"
  • 文案："预计X月X日左右来，你的周期不太规律，这次预测有一定不确定性"
  • 置信区间：±4-5天，显著展示
  • 交互：默认展开"为什么有不确定性"说明
  • 行动指引："多记录症状和睡眠数据，可以提高预测准确度"
  • 推送：经期前3天提醒，文案含"可能在这几天来"
🔴 Low Confidence（<50%）
  • 展示：不给确定日期，显示预测范围
  • 文案："你的数据还不够，我们暂时无法给出准确预测。根据现有数据，可能在X月X日-X月X日之间来。"
  • 置信区间：±7天以上，显著展示
  • 交互：默认展示"如何提高预测准确度"引导
  • 行动指引："再记录N个周期，或接入睡眠/运动数据，预测会更准"
  • 推送：不推送具体日期提醒，改为"近期可能来经期，建议准备"
  • 红线：低置信度下绝对不显示"预计X日来"这种确定性表述

3.3 预测依据展示规则

点击"为什么这么预测"进入预测依据页，展示：

  1. 使用的数据：周期历史（N个周期）、睡眠（已接入/未接入）、运动（已接入/未接入）、症状（N条记录）
  2. 关键影响因素：本次预测中权重最高的3个因素（如"近3个月周期波动较大""本月睡眠质量下降"）
  3. 模型说明："我们使用AI模型综合分析你的周期规律和生活方式数据，数据越多预测越准"
  4. 隐私说明："你的数据仅用于你的个人预测，不会用于其他用途"

3.4 推迟场景的置信度重算

当预测日期到达但经期未开始时，触发置信度重算：

  1. 推迟1-3天：置信度可能下降，显示"比预测晚了X天，仍在正常波动范围内"
  2. 推迟4-7天：置信度显著下降，显示"推迟时间较长，可能原因：压力/睡眠/运动变化"
  3. 推迟7天以上：触发"需关注"状态，显示"如果持续推迟，建议咨询医生"，明确就医红线
Design Principle
推迟场景下，绝对不使用"警告""异常""可能怀孕"等引发焦虑的词汇。改用"推迟说明""可能原因""建议观察"等中性、赋能性表述。

4. 页面状态与交互

4.1 首页预测卡片（3种状态）

元素HighMediumLow
主标题"预计X月X日来""预计X月X日左右来""可能在X月X日-X月X日来"
置信度标签绿色"预测较准"黄色"有一定不确定性"红色"数据不足"
置信区间小字±2天显著±4-5天显著±7天+
行动按钮"查看详情""了解为什么""如何提高准确度"
背景色正常淡黄色提示淡红色提示

4.2 预测详情页

  1. 顶部：预测日期 + 置信度进度条（0-100%）+ 置信区间
  2. 中部："为什么这么预测" — 预测依据卡片（使用的数据、关键影响因素）
  3. 下部："如何提高预测准确度" — 行动建议（多记录、接入更多数据）

4.3 推迟说明页

  1. 顶部："比预测晚了X天" + 当前置信度
  2. 分级标签：正常波动（绿）/ 需关注（黄）/ 建议就医（红）
  3. 可能原因：基于用户数据的个性化分析（如"近期睡眠质量下降""本月运动量骤减"）
  4. 行动指引：继续观察 / 记录更多症状 / 咨询医生（明确就医红线：推迟14天以上、伴随剧烈疼痛等）

5. 正常流程与异常情况

5.1 正常流程

// 日常查看预测
用户打开App → 首页显示预测卡片（含置信度等级）
→ 用户点击"查看详情" → 预测详情页（置信度进度条+预测依据）
→ 用户点击"为什么这么预测" → 预测依据展开
→ 用户关闭页面
// 记录后预测更新
用户记录经期开始 → 系统更新周期数据
→ 触发预测重算 → 置信度可能提升（数据量增加）
→ 首页显示"预测已更新" + 新的置信度等级
→ Toast提示"记录成功，预测准确度已提升"

5.2 异常情况

异常场景系统行为用户体验
新用户，数据不足3个周期强制Low Confidence状态诚实告知"数据不足"，引导多记录
AI模型服务不可用降级为日历法预测，标注"基础预测"显示"AI服务暂时不可用，当前为基础预测"
用户关闭所有数据授权仅用周期历史预测，置信度上限70%预测依据页显示"未接入睡眠/运动数据，预测准确度有限"
预测日期到达但未开始触发推迟流程，置信度重算显示推迟说明+分级+可能原因
用户连续3个月周期波动极大（标准差>10天）置信度上限60%，建议就医"你的周期波动较大，建议咨询医生了解原因"

8. 验收标准（Acceptance Criteria）

8.1 功能验收

  • 首页预测卡片根据置信度显示3种不同状态（高/中/低），文案、颜色、交互均不同
  • 高置信度（≥80%）显示确定日期+±2天区间，不主动展开不确定性说明
  • 中置信度（50-80%）显示"左右"+±4-5天区间，默认展开不确定性说明
  • 低置信度（<50%）不显示确定日期，只显示日期范围+行动指引
  • 数据不足3个周期的新用户，强制进入低置信度状态
  • 点击"为什么这么预测"可查看预测依据（使用的数据+关键影响因素）
  • 记录经期后，预测自动重算，置信度可能变化，并给出"预测已更新"反馈
  • 推迟场景触发置信度重算，显示分级说明（正常波动/需关注/建议就医）
  • 推迟7天以上显示"建议咨询医生"，明确就医红线
  • AI服务不可用时降级为日历法，并标注"基础预测"

8.2 体验验收

  • 所有置信度相关文案不使用"警告""异常""可能怀孕"等焦虑性词汇
  • 低置信度状态下，绝对不出现"预计X日来"这种确定性表述
  • 置信度进度条、等级标签、区间展示在3种状态下视觉区分明显
  • 预测依据页清晰展示使用了哪些数据，未授权数据标注"未启用"
  • "如何提高准确度"给出具体、可执行的建议（而非泛泛而谈）
  • 5-8人可用性测试中，用户能正确理解3种置信度状态的含义（任务完成率≥80%）

8.3 数据验收

  • 所有埋点事件正确触发，参数完整
  • 置信度查看率可追踪（prediction_card_click / prediction_card_view）
  • 低置信度用户的记录提升率可对比分析
  • 预测MAE可按置信度分级统计（高/中/低分别计算）

9. 风险与依赖

风险影响缓解措施
置信度计算模型不准确用户看到错误的置信度，反而降低信任MVP阶段用规则引擎而非纯AI，基于数据量/规律性等可解释因素计算
用户不理解"置信度"概念功能形同虚设用"预测较准/有一定不确定性/数据不足"等通俗语言，而非纯百分比
低置信度让用户觉得产品没用新用户流失低置信度伴随明确的"如何提高"行动指引，将劣势转化为参与动机
推迟场景的医疗建议风险用户依赖App判断是否就医，延误治疗明确标注"不能替代医生诊断"，就医红线保守设置，建议咨询而非诊断
