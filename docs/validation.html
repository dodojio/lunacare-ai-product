Note
以下为 Proposed 验证方案和指标体系。概念产品阶段用于定义成功标准和验证方向，非实际运行数据。建议完成至少一轮5-8人可用性测试，将LunaCare从"课堂作业感"变成真正的产品作品。

1. 可用性测试计划

1.1 测试概述

项目内容
测试目标验证LunaCare核心设计假设：置信度透明是否能降低用户焦虑、提高信任度
参与者5-8人，优先周期不规律且使用过经期App的女性用户
招募标准18-35岁女性；周期不规律（标准差>3天）；使用过至少1款经期追踪App
测试方法远程屏幕共享 + 出声思考（Think Aloud）+ 半结构化访谈
单场时长45-60分钟（5分钟暖场 + 25分钟任务 + 20分钟访谈）
测试原型Figma高保真可交互原型（10个核心界面）

1.2 三个核心任务

任务 1 — 查看预测并理解可信度
"请查看你下次经期的预测时间，并告诉我你认为这个预测有多可信。"
成功标准：用户能找到预测日期（≤10秒）；能说出置信度等级和含义；理解"中等置信度"意味着什么
任务 2 — 记录今天经期开始
"假设你今天经期开始了，请在App中完成记录。"
成功标准：用户能在3步内完成记录；注意到AI推荐的症状标签；理解"记录后预测会更新"
任务 3 — 经期推迟5天，判断是否需要担心
"假设你的经期比预测晚了5天还没来，请在App中了解情况，并告诉我你接下来会怎么做。"
成功标准：用户能找到推迟说明；理解"需关注"分级；能说出至少1个可能原因；知道什么时候该就医；不感到被"警告"吓到

1.3 记录指标

指标定义目标
任务完成率3个任务中独立完成的比例≥80%
任务完成时间每个任务从开始到完成的时间任务1≤30秒，任务2≤60秒，任务3≤90秒
用户理解度测试后问卷中对置信度概念的理解评分（1-5）≥4.0
焦虑感评分推迟场景后用户自我报告的焦虑程度（1-5）≤2.5（低于传统"警告"模式）
错误点用户操作中出现的困惑、误点击、找不到入口每任务≤1个
用户原话记录用户的关键反馈和金句每用户≥3条有价值反馈
SUS评分系统可用性量表（System Usability Scale）≥70分（良好）

1.4 测试后访谈问题

  1. 你觉得"预测置信度"这个功能有用吗？为什么？
  2. 看到"中等置信度"时，你的感受是什么？会影响你对App的信任吗？
  3. 推迟场景的说明和你之前用过的App有什么不同？你更喜欢哪种？
  4. 你觉得AI推荐症状标签准确吗？会使用吗？
  5. 如果这个App真的上线，你愿意用吗？愿意付费吗？
  6. 你觉得最需要改进的地方是什么？

3. A/B 测试计划（上线后）

实验 1 — 置信度展示方式

对照组：百分比数字（72%）

实验组A：进度条 + 文字描述（"中等置信度"）

实验组B：三档标签（高/中/低）+ 颜色

假设：进度条+文字描述的理解度最高，焦虑感最低；纯百分比对非技术用户不友好

核心指标：Confidence查看率、用户理解度（问卷）、焦虑感评分

实验 2 — 推迟场景文案

对照组：传统"经期延迟"警告（红色+感叹号）

实验组：LunaCare分级说明（"比预测晚了X天"+可能原因+建议）

假设：分级说明能显著降低用户焦虑感，同时提高行动率（记录症状/设置提醒）

核心指标：推迟说明阅读率、焦虑相关差评率、推迟场景下的记录率

实验 3 — AI推荐症状

对照组：纯手动选择症状标签

实验组：AI推荐3个症状 + 手动补充

假设：AI推荐能提高记录完成率和记录丰富度，同时降低记录时间

核心指标：记录完成率、平均记录时间、每记录平均症状数

实验 4 — 低置信度行动引导

对照组：仅显示"数据不足，预测不准"

实验组：显示"数据不足"+具体行动指引（"再记录2个周期可提升至80%"）

假设：具体行动指引能将低置信度用户的7日记录率从15%提升至30%+

核心指标：低置信度用户记录提升率、新用户7日留存

4.1 迭代流程

  1. V1 原型完成：10个核心界面的高保真可交互原型
  2. 可用性测试：5-8人，3个核心任务，记录完成率/时间/错误/用户原话
  3. 反馈综合：
    • 量化分析：任务完成率、SUS评分、焦虑感评分
    • 定性分析：用户原话聚类、痛点优先级排序
    • 输出：Top 5 问题清单 + 改进建议
  4. V2 原型迭代：基于反馈修改原型，重点改进Top 3问题
  5. （可选）第二轮测试：3-5人验证关键问题是否解决

4.2 预期可能发现的问题（预设假设）

预设问题风险等级可能的V2改进方向
用户不理解"置信度"概念高改用更通俗的语言（"预测较准/有一定不确定性/数据不足"），增加首次使用引导
低置信度让用户觉得产品没用中强化"如何提高准确度"的行动指引，将劣势转化为参与动机
推迟说明信息过载中默认只显示分级和核心建议，可能原因折叠为"查看详情"
AI推荐症状不准确低增加"不推荐"反馈按钮，优化推荐算法
用户担心隐私中Onboarding中更突出隐私模式选择，增加端侧模式说明

4.3 验证完成后的产出

  • 可用性测试报告（含量化数据+定性发现+用户原话）
  • V2改进版原型
  • 迭代记录（V1→V2改了什么、为什么改、效果如何）
  • 作品集更新：在Case Study中增加"验证与迭代"章节
Why This Matters
完成一轮真实的可用性测试并展示V1→V2迭代，是将LunaCare从"课堂作业感"变成"真正产品作品"的关键。面试官看到的不是一个完美的设计，而是一个会学习、会迭代的产品经理。这比任何精美的界面都更有说服力。
